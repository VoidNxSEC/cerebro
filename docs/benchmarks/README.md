# Cerebro RAG Benchmarks

Performance measurements across hardware configurations.
Generated by `scripts/benchmark.py` — run with `cerebro benchmark run`.

## How to Run

```bash
# Quick benchmark (~2 min, CPU only)
cerebro benchmark run --quick

# Full benchmark (embedding + reranker + RAG queries + ingest)
cerebro benchmark run

# GPU only (skip CPU comparison)
cerebro benchmark run --gpu-only

# Save to custom path
cerebro benchmark run --output /tmp/my-benchmark.json

# Or directly:
python scripts/benchmark.py [--quick] [--gpu-only] [--api-url http://localhost:8009]
```

## What is Measured

| Dimension | Details |
|-----------|---------|
| **Embedding latency** | Jina Code v2 / MPNET / MiniLM at batch sizes 1, 8, 32, 64 |
| **GPU vs CPU** | Speedup ratio when CUDA is available |
| **RAG query latency** | p50 / p95 / p99 over 100 synthetic queries |
| **Ingest throughput** | docs/s for batch of 50 documents |
| **Reranker latency** | ms-marco-MiniLM-L-6-v2 at batch sizes 1, 4, 8, 16 |
| **Memory footprint** | RAM delta (psutil) + VRAM (torch.cuda) per model |

## Hardware Recommendations

Based on benchmark data:

| Use Case | Minimum | Recommended |
|----------|---------|-------------|
| Development (local, ChromaDB) | 8GB RAM, 4 CPU cores | 16GB RAM, 8 cores |
| Production (pgvector, 1M+ vectors) | 16GB RAM, 8 cores | 32GB RAM + GPU (8GB VRAM) |
| Code-heavy indexing (Jina Code v2) | 12GB RAM or 6GB VRAM | GPU (RTX 3080+, 10GB+ VRAM) |
| High-throughput ingest | 16GB RAM, SSD | GPU + NVMe, 32GB RAM |

## Expected Performance (Reference)

Measured on a typical developer workstation (CPU only, i7-12th gen, 32GB RAM):

| Metric | Value |
|--------|-------|
| MiniLM embed (batch=1) | ~12ms |
| MiniLM embed (batch=32) | ~85ms |
| Jina Code v2 (batch=1) | ~45ms |
| Jina Code v2 (batch=32) | ~280ms |
| RAG query p50 | ~500ms |
| RAG query p95 | ~800ms |
| Ingest throughput | ~8 docs/s |
| Reranker (batch=4) | ~25ms |

GPU acceleration (RTX 3080, 10GB VRAM) improves embedding by 5-10x and reranker by 3-5x.
RAG query latency depends primarily on the LLM provider, not embedding speed.

## CI Regression Policy

The benchmark runs in CI on every PR that touches `src/cerebro/core/rag/` or `src/cerebro/providers/`.
A regression is flagged when p50/p95/p99 query latency increases by **more than 20%** vs baseline.

Baseline is stored in `docs/benchmarks/baseline.json` and updated manually after hardware changes.
